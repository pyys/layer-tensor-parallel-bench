# V100-SXM2 16GB ×4 — 파생 지표

[`v100-sxm2-16gb-x4.ko.md`](v100-sxm2-16gb-x4.ko.md) 의 부속 문서. 계산식은
[METHOD 5절](../METHOD.ko.md) 에 있다.

> ⚠️ **영문 [`v100-sxm2-16gb-x4-metrics.md`](v100-sxm2-16gb-x4-metrics.md) 이 정본이다.**

원본 수치는 [`../results/v100-sxm2-16gb-x4.jsonl`](../results/v100-sxm2-16gb-x4.jsonl).
아래 값은 모두 **웜 4턴 평균** 기준이며, 콜드는 1회 측정이다.

**이 플랫폼은 `tg_1` 이 실측값이다.** 모델 13,115 MiB 가 16GB 카드 한 장에 들어가
`layer-nomtp-1` 을 직접 쟀다. P104 보고서의 환산값과 달리 아래 스케일링 효율은
추정에 의존하지 않는다.

## 1. 세션 소요와 손익분기

세션 = 콜드 1회 + 웜 N회. 벽시계 기준이다.

| 구성 | 소요 |
|---|---|
| layer / off / 4장 | 29.19 + **16.2N** 초 |
| layer / off / 2장 | 35.42 + **15.9N** 초 |
| layer / off / 1장 | 45.19 + **16.0N** 초 |
| tensor / off / 4장 | 34.68 + **9.9N** 초 |
| tensor / off / 2장 | 29.85 + **10.8N** 초 |

```
손익분기 N = (콜드_A − 콜드_B) / (웜_B − 웜_A)
```

| 손익분기 | 턴 |
|---|---|
| tensor 4장 > layer 4장 | **0.87** |
| tensor 2장 > layer 4장 | **0.12** |
| tensor 4장 > tensor 2장 | **5.4** |

**첫 웜 턴부터 텐서가 이긴다.** P104 에서는 1.2턴 / 2.4턴이었다 — 콜드 격차가
컸기 때문이다. V100 에서는 콜드 차이가 5.5초로 줄어 역전이 거의 즉시 일어난다.

**세 번째 줄이 실무적으로 중요하다.** 텐서 병렬끼리도 카드 수에 따라 유불리가
갈린다 — **5턴을 넘지 않는 세션이면 2장이 4장보다 빠르다.** 4장은 콜드가 4.8초
느린데(34.68 대 29.85) 웜에서 턴당 0.9초밖에 못 벌기 때문이다.

⚠️ 이 값들은 **웜 턴이 4턴 평균**이라는 전제 위에 있다. 턴이 길어지면 KV 가 커져
웜 턴 소요가 늘어난다 — 선형 외삽은 짧은 세션에서만 유효하다.

## 2. 텐서 병렬 스케일링 효율

```
효율(N) = (tg_tensor(N) / tg_1) / N
```

**`tg_1` = 27.71 t/s (`layer-nomtp-1` 실측).**

| N | tensor tg | 배수 | **효율** |
|---|---|---|---|
| 1 | 27.45 | 0.99배 | — |
| 2 | 41.64 | 1.50배 | **75%** |
| 3 | 42.79 | 1.54배 | **51%** |
| 4 | 46.62 | 1.68배 | **42%** |

### 2-1. P104 대비 — 대역폭이 16배인데 효율이 더 나쁘다

| N | P104 배수 | P104 효율 | **V100 배수** | **V100 효율** |
|---|---|---|---|---|
| 2 | 1.62배 | 81% | 1.50배 | **75%** |
| 3 | 1.77배 | 59% | 1.54배 | **51%** |
| 4 | 2.29배 | 57% | **1.68배** | **42%** |

**인터커넥트 대역폭을 Gen1 x4 → Gen3 x16 으로 16배 올렸는데 효율이 전 구간에서
떨어졌다.** 대역폭은 연산(5.7배)보다 2.8배 더 크게 좋아졌는데도 그렇다.

P104 만 있었을 때 이 저장소는 감쇠의 원인을 **PCIe Gen1 x4** 로 추정했다.
**그 추정은 반증됐다.** 원인은 미확정이며, 스텝마다의 동기화 지연이나 all-reduce
자체의 고정비가 후보다. 자세한 논의는 [FINDINGS 5](../FINDINGS.ko.md) 에 있다.

### 2-2. P104 의 환산이 옳았음이 확인됐다

P104 에서는 `tg_1` 을 **레이어 분산의 tg 로 대용**했다. V100 에서 그 전제를
실측과 대조할 수 있다.

| | 값 |
|---|---|
| **1장 실측** | **27.71** |
| 레이어 2장 | 27.97 (+0.9%) |
| 레이어 3장 | 27.78 (+0.2%) |
| 레이어 4장 | 27.29 (−1.5%) |

**전부 1.5% 안에 든다.** 레이어 분산은 한 시점에 한 장만 계산하므로 그 값이 곧
1장 속도라는 전제가 성립한다. **P104 효율 수치의 신뢰도가 올라간다.**

## 3. MTP 배치 경제학

투기적 디코딩의 손익은 **검증 배치의 비용 배수**가 정한다.

```
스텝 수      = n_predict − draft_n_accepted
스텝당 비용  = predicted_ms(MTP 켬) / 스텝 수
토큰당 비용  = predicted_ms(MTP 끔) / n_predict
비용 배수    = 스텝당 비용 ÷ 토큰당 비용
스텝당 산출  = n_predict / 스텝 수
```

**산출 < 비용 배수이면 MTP 는 손해다.**

### 3-1. 다섯 셀 전부

웜 4턴 합계 기준이다. `tensor-mtp-4` 는 Xid 79 로 측정되지 않았다.

| | layer 4 | layer 3 | layer 2 | **tensor 3** | **tensor 2** |
|---|---|---|---|---|---|
| 드래프트 / 수락 (4턴 합) | 2440 / 780 | 2440 / 780 | 2440 / 780 | 2547 / 744 | 2599 / 723 |
| 턴당 스텝 수 | 205 | 205 | 205 | 214 | 219.25 |
| 드래프트 길이 | 2.976 | 2.976 | 2.976 | 2.975 | 2.964 |
| MTP 끔, 토큰당 | 36.56 ms | 35.91 ms | 35.67 ms | **23.31 ms** | **23.96 ms** |
| MTP 켬, **스텝당** | 69.14 ms | 67.87 ms | 66.32 ms | 49.70 ms | 46.59 ms |
| **비용 배수** | **1.891** | **1.890** | **1.859** | **2.132** | **1.944** |
| 스텝당 산출 | 1.951 | 1.951 | 1.951 | 1.869 | 1.824 |
| **예측 손익** | **+3.2%** | **+3.2%** | **+5.0%** | **−12.3%** | **−6.2%** |
| **실측 손익** | **+3.5%** | **+3.4%** | **+5.2%** | **−12.1%** | **−5.9%** |

**예측과 실측이 다섯 셀 전부에서 0.3%p 안에 든다.** 모델이 유효하다는 증거다.

### 3-2. 손익분기 수락률

```
드래프트 길이 d = draft_n / 스텝 수
1 + d × acc = 비용 배수   ->   acc = (비용 배수 − 1) / d
```

| | layer 4 | layer 3 | layer 2 | **tensor 3** | **tensor 2** |
|---|---|---|---|---|---|
| **손익분기 수락률** | **29.9%** | **29.9%** | **28.9%** | **38.1%** | **31.9%** |
| 실측 수락률 | **32.0%** | **32.0%** | **32.0%** | 29.2% | 27.8% |
| 판정 | **이득** | **이득** | **이득** | 손해 | 손해 |

**레이어 세 셀의 수락률이 32.0% 로 완전히 같다.** 드래프트·수락 수까지 동일하다 —
레이어 분산은 N 과 무관하게 결정적이다(METHOD 6-2).

⚠️ 본 측정의 수락률은 `ignore_eos` 로 400토큰을 강제 생성해 모델이 끝내려는 지점을
넘겼기 때문에 **실사용보다 낮다**(METHOD 1-5).

### 3-3. 같은 카드에서 분할 방식이 부호를 가른다

```
layer   비용 배수 1.89,  손익분기 29.9%,  수락률 32.0%   ->  이득
tensor  비용 배수 2.13,  손익분기 38.1%,  수락률 29.2%   ->  손해
```

**두 가지가 같은 방향으로 벌어진다.**

**(a) 비용 배수가 높다.** 텐서 병렬이 **단일 토큰 디코드를 싸게 만들기 때문**이다.
토큰당 비용이 35.9 → 23.3 ms 로 떨어지는데 배치 4 검증 비용은 그만큼 떨어지지
않으므로, **분모가 작아져 배수가 커진다.**

**(b) 수락률이 낮다.** 텐서 병렬은 N 이 바뀌면 생성 내용 자체가 달라진다
(METHOD 6-2). 레이어가 `2440 / 780` 으로 고정인 반면 텐서는 `2547/744`,
`2599/723` 으로 제각각이다. **이 차이를 GPU 수의 효과로 읽으면 안 된다.**

### 3-4. P104 대비

| | P104 layer 4 | **V100 layer 4** |
|---|---|---|
| **비용 배수** | 2.25 | **1.891** |
| 손익분기 수락률 | 42.3% | **29.9%** |
| 실측 수락률 | 29.9% | 32.0% |
| 판정 | **−16.3%** | **+3.5%** |

**수락률은 29.9% → 32.0% 로 거의 그대로인데 부호가 뒤집혔다.** 바뀐 것은
**손익분기선**이다. 원리는 [FINDINGS 4](../FINDINGS.ko.md) 에 있다.

## 4. 루프라인

```
실효 대역폭 = (모델 크기 / N) ÷ 카드가 실제로 쓰는 시간
```

모델 12.81 GiB, 토큰당 전체를 한 번 읽는다. 사양 대역폭은 900 GB/s (HBM2).

| 구성 | 카드가 쓰는 시간 | 실효 대역폭 | 사양 대비 |
|---|---|---|---|
| **1장 (실측)** | 36.00 ms | **382 GB/s** | **42%** |
| layer 4장 | 36.56 ms 의 1/4 = 9.14 ms | 376 GB/s | **42%** |
| tensor 2장 | 23.96 ms (두 장 동시) | 287 GB/s | 32% |
| tensor 3장 | 23.31 ms (세 장 동시) | 197 GB/s | 22% |
| tensor 4장 | 21.40 ms (네 장 동시) | 161 GB/s | **18%** |

**전부 사양의 절반 미만이다. 디코드는 메모리 대역폭에 묶여 있지 않다.**

**1장과 layer 4장이 같은 42% 인 것은 예측대로다.** 레이어 분산은 같은 일을
직렬화할 뿐이므로 카드당 활용률이 1장과 같아야 한다. **실측이 그 구조를 확인한다.**

**텐서 병렬은 카드를 늘릴수록 활용률이 떨어진다**(32% → 22% → 18%). 통신 대기가
끼어들기 때문이다. 그럼에도 전체 처리량은 4장이 가장 높은데 **네 장이 동시에
일하기 때문**이다. 2절의 확장 효율 하락과 같은 현상을 다른 각도에서 본 것이다.

### P104 대비

| 구성 | P104 (사양 320 GB/s) | **V100 (사양 900 GB/s)** |
|---|---|---|
| layer 4장 | 108 GB/s (**34%**) | 376 GB/s (**42%**) |
| tensor 4장 | 62 GB/s (19%) | 161 GB/s (**18%**) |

**V100 이 대역폭을 더 쓴다**(34% → 42%). 이것이 3절에서 비용 배수가 2.25 → 1.89 로
내려간 이유와 같은 뿌리다 — **덜 연산 바운드**이므로 배치 4 검증이 덜 비싸다.
**"대역폭 바운드가 됐다"는 뜻이 아니다.** 여전히 절반 미만이다.

## 5. SM 클럭 스윕 — 디코드는 무엇에 묶여 있는가

4절의 루프라인은 **대역폭을 얼마나 쓰는지**를 보여줄 뿐 인과를 보여주지 않는다.
클럭을 직접 낮추면 인과를 잰다.

**V100 은 메모리 클럭이 877 MHz 하나뿐이라 대역폭을 조일 수 없다.** 따라서 반대로
**코어 클럭만 낮추고 대역폭은 묶어 둔다.**

`layer-nomtp-1` 을 GPU0 한 장에서 `nvidia-smi -lgc` 로 클럭을 고정해 돌렸다.
분할도 통신도 없으므로 카드 자체의 거동만 남는다.

| 요청 | 실제 클럭 | 클럭비 | **tg** | tg비 | 토큰당 시간 |
|---|---|---|---|---|---|
| 1530 | **1507** | 1.000 | **27.67** | 1.000 | 36.14 ms |
| 1230 | 1230 | 0.816 | 23.78 | 0.859 | 42.05 ms |
| 930 | 930 | 0.617 | 18.74 | 0.677 | 53.36 ms |
| 630 | 630 | 0.418 | 12.69 | 0.459 | 78.80 ms |
| 330 | 330 | 0.219 | **4.74** | 0.171 | 210.97 ms |

**클럭을 4.57배 낮추자 tg 가 5.84배 떨어졌다.**

### 5-1. 구간별 기울기

로그-로그 기울기다. `d(ln tg) / d(ln 클럭)` 이며, **1.0 은 tg 가 클럭에 정비례함을,
0 은 클럭과 무관함을 뜻한다.**

| 구간 | 기울기 |
|---|---|
| 1507 → 1230 | **0.75** |
| 1230 → 930 | 0.85 |
| 930 → 630 | **1.00** |
| 630 → 330 | **1.52** |

### 5-2. 330 MHz 는 다른 구간과 다르게 움직인다

기울기 1.52 는 **위 세 구간과 성격이 다르다.** 콜드 프리필도 같은 지점에서 함께
꺾인다 — 클럭비 0.219 에 대해 125.0 / 752.9 = **0.166** 이다.

**두 지표가 같이 벗어나므로 측정 잡음은 아니다.** 원인은 조사하지 않았다.

### 5-3. 이 측정의 성격

**동결 방법론 밖의 보조 측정이다.** `nvidia-smi -lgc` 는 METHOD 3절의 허용 변동
목록에 없다. 12셀 매트릭스와 같은 표에 넣어 비교하지 않는다.

측정 후 `-rgc` 로 복원했다. 원시 데이터는
[`../results/clocksweep.jsonl`](../results/clocksweep.jsonl) 에 클럭당 한 줄씩
있으며, 각 줄에 `validity: side` 와 **`locked_clock_mhz` · `actual_clock_mhz`** 가
들어 있다. 실제 클럭은 텔레메트리 CSV 에서 **GPU 사용률 50% 초과 구간의 최빈값**을
뽑은 것이다.
