# P104-100 8GB ×4 — 파생 지표

[`p104-100-x4.ko.md`](p104-100-x4.ko.md) 의 부속 문서. 계산식은

> ⚠️ **V100 16GB PCIe ×4 측정 결과가 나오면 수정될 수 있다.** 특히 스케일링
> 효율은 단일 플랫폼에서 나온 값이고, 1장 기준선이 실측이 아니라 환산값이다.
>
> ⚠️ **영문 [`p104-100-x4-metrics.md`](p104-100-x4-metrics.md) 이 정본이다.**

아래 값은 모두 **웜 4턴 평균** 기준이며, 콜드는 1회 측정이다.

## 1. 세션 소요와 손익분기

세션 = 콜드 1회 + 웜 N회.

| 구성 | 소요 |
|---|---|
| layer / off / 4장 | 119.8 + **59.7N** 초 |
| layer / off / 2장 | 157.7 + **57.9N** 초 |
| tensor / off / 4장 | 156.6 + **28.1N** 초 |
| tensor / off / 2장 | 174.2 + **36.9N** 초 |

```
손익분기 N = (콜드_A − 콜드_B) / (웜_B − 웜_A)
```

| 손익분기 | 턴 |
|---|---|
| tensor 4장 > layer 4장 | **1.2** |
| **tensor 2장 > layer 4장** | **2.4** |

텐서 병렬은 콜드가 느리므로 첫 턴에서는 진다. 그러나 **두세 번째 메시지부터
역전되고**, 그 뒤로는 격차가 턴마다 벌어진다.

**카드 2장 텐서 병렬이 카드 4장 레이어 분산을 3턴이면 따라잡는다**는 것이
이 표의 핵심이다.

---

## 2. 텐서 병렬 스케일링 효율

```
효율(N) = (tg_tensor(N) / tg_1) / N
```

⚠️ **`tg_1` 은 실측이 아니다.** 모델(13,115 MiB)이 8GB 카드 한 장에 들어가지
않아 측정할 수 없었다. **레이어 분산의 `tg` 를 대용**한다 — 레이어 분산은 한
시점에 한 장만 계산하므로(본문 3-1) 그 값이 곧 1장 속도다. **환산값이다.**

| N | tensor tg | layer tg (=1장) | 배수 | **효율** |
|---|---|---|---|---|
| 2 | 13.06 | 8.08 | 1.62배 | **81%** |
| 3 | 14.14 | 7.97 | 1.77배 | **59%** |
| 4 | 17.89 | 7.82 | 2.29배 | **57%** |

2장까지는 잘 붙고 그 이상은 급격히 나빠진다. 3장이 특히 나쁜 것은 NCCL 의
링/버터플라이 알고리즘이 2의 거듭제곱에서 유리하기 때문으로 보이나 **미검증**이다.

메모리 대역폭은 병목이 아니므로(4절), 이 감쇠의 원인은 **PCIe Gen1 x4
인터커넥트**로 추정된다.

## 3. MTP 배치 경제학

투기적 디코딩의 손익은 **검증 배치의 비용 배수**가 정한다.

```
스텝 수      = n_predict − draft_n_accepted
스텝당 비용  = predicted_ms(MTP 켬) / 스텝 수
토큰당 비용  = predicted_ms(MTP 끔) / n_predict
비용 배수    = 스텝당 비용 ÷ 토큰당 비용
스텝당 산출  = n_predict / 스텝 수
```

**산출 < 비용 배수이면 MTP 는 손해다.**

| | layer 4장 | tensor 4장 |
|---|---|---|
| MTP 끔, 토큰당 | 127.9 ms | 55.9 ms |
| MTP 켬, **스텝당** | 288.3 ms | 135.5 ms |
| **비용 배수** | **2.25** | **2.42** |
| 드래프트 길이 | 2.97 | 2.98 |
| 스텝당 산출 | 1.89 토큰 | 1.99 토큰 |
| **예측 손실** | **−16.2%** | **−18.1%** |
| **실측 손실** | **−16.3%** | **−17.2%** |

**예측과 실측이 0.1~0.9%p 안에서 맞는다.** 모델이 유효하다는 증거다.

### 손익분기 수락률

```
드래프트 길이 d = draft_n / 스텝 수
1 + d × acc = 비용 배수   ->   acc = (비용 배수 − 1) / d
```

| | layer 4장 | tensor 4장 |
|---|---|---|
| **손익분기 수락률** | **42.3%** | **47.8%** |
| 본 측정 수락률 (무정 픽스처) | 29.9% | 33.1% |
| 실사용 관측 수락률 | 47.9% | 47.9% |

본 측정에서는 손익분기에 한참 못 미쳐 16~18% 손해다. 실사용 수락률(47.9%)을
대입하면 **기껏해야 본전**이다.

⚠️ 본 측정의 수락률이 낮은 것은 `ignore_eos` 로 400토큰을 강제 생성해 모델이
끝내려는 지점을 넘겼기 때문이다(METHOD 1-5). 따라서 **"실사용에서 본전"이라는
판정은 손익분기 역산에 의한 외삽**이며 직접 측정이 아니다.

### 왜 이 값이 중요한가

투기적 디코딩 문헌은 **배치 1이 대역폭 바운드라 검증이 거의 공짜**라고 전제한다.
비용 배수가 2.25~2.42 라는 것은 **이 카드에서 그 전제가 배치 1에서도 깨진다**는
뜻이고, 곧 **연산 바운드**라는 직접 증거다.

같은 계산은 어떤 llama.cpp 실행에도 적용할 수 있다. `draft_n`, `draft_n_accepted`,
`predicted_ms` 만 있으면 된다.

## 4. 루프라인

```
실효 대역폭 = 카드가 읽는 바이트 ÷ 그 카드가 쓰는 시간
```

모델 12.81 GiB, 토큰당 전체를 한 번 읽는다.

| 구성 | 계산 | 실효 대역폭 | 사양(320 GB/s) 대비 |
|---|---|---|---|
| layer 4장 | 카드당 3.20 GiB ÷ 32.0 ms (전체 128 ms 의 1/4 동안만 활성) | 108 GB/s | **34%** |
| tensor 4장 | 카드당 3.20 GiB ÷ 55.9 ms (네 장 동시) | 62 GB/s | **19%** |

둘 다 사양의 1/3 이하다. **디코드는 메모리 대역폭에 묶여 있지 않다.**

흥미로운 점은 **레이어 분산 쪽이 카드당 대역폭 활용률은 더 높다**는 것이다(34%
대 19%). 텐서 병렬은 통신 대기가 끼어들기 때문이다. 그럼에도 전체 처리량은
텐서 병렬이 2.3배인데, **네 장이 동시에 일하기 때문**이다.

### Q6 와의 비교

| | 모델 크기 | tensor 4장 tg | 실효 대역폭 |
|---|---|---|---|
| Q6_K | 20.88 GiB | 18.39 | 96 GB/s (30%) |
| Q3_K_M | 12.81 GiB | 17.89 | 62 GB/s (19%) |

**바이트를 39% 덜 읽었는데 속도가 같고, 대역폭 활용률만 떨어졌다.** 대역폭이
병목이라면 있을 수 없는 결과다.

⚠️ Q6 값은 llama-bench(저컨텍스트), Q3 값은 서버(23k 컨텍스트)에서 잰 것이라
하네스가 다르다. 이 비교만으로는 약하며, 3절의 배치 경제학이 독립적 근거다.
