# GTX 1080 Ti ×4 (PCIe Gen3 x4/x8 혼재) — 레이어 병렬 vs 텐서 병렬

측정일 2026-11-12. 방법론 **METHOD v1.5** ([`../METHOD.ko.md`](../METHOD.ko.md)) — v1.5 는 이 측정을 위해
3절에 **비대칭 장치 선택** 조항을 추가한 개정이다(측정 조건 자체는 v1.0~v1.4 와 같다).
원시 데이터 [`../results/gtx1080ti-x4.jsonl`](../results/gtx1080ti-x4.jsonl) — 주 측정 `validity: ok` / `invalid`,
보조 측정 `side`, 재측정 `invalid`.
파생 지표는 별도 문서 [`gtx1080ti-x4-metrics.ko.md`](gtx1080ti-x4-metrics.ko.md).

> 측정 조건은 METHOD 에 있다. 여기에는 이 플랫폼의 **환경·결과·해석만** 적는다.
> 두 플랫폼을 가로지르는 결론은 [`../FINDINGS.ko.md`](../FINDINGS.ko.md) 에 있다.
>
> ⚠️ 영문 [`gtx1080ti-x4.md`](gtx1080ti-x4.md) 이 정본이다.

[P104-100 ×4 Gen1 x1](p104-100-x4-gen1x1.ko.md) 과 **같은 호스트·같은 드라이버·같은 바이너리·같은 모델 파일**에서 카드만 바꿨다
([Gen1 x4 측정](p104-100-x4.ko.md)과는 커밋·모델이 같지만 호스트·드라이버·빌드가 다르다).
P104 는 퓨즈로 Gen1 x4 에 묶여 있었고, 1080 Ti 는 같은 Pascal(sm_61) 이면서 **Gen3 로 붙는다.**
링크가 4~8배 넓어지고 카드 연산이 약 1.8배가 되었을 때 기존 결론 — "텐서 병렬이 양쪽에서 이긴다",
"레이어 분산은 디코드 이득이 0" — 이 유지되는지, 그리고 **텐서 프리필이 장수에 따라 어떻게 변하는지**를 본다.

## 1. 환경

### 하드웨어

| 항목 | 값 |
|---|---|
| GPU | NVIDIA GeForce GTX 1080 Ti ×4 (GP102, sm_61, 블로워·오픈팬 혼재 여부 미기록) |
| VRAM | 장당 11,264 MiB / 합계 44 GiB |
| 메모리 대역폭 | 484 GB/s (사양) |
| 전력 상한 | 250 W (카드 기본값, 조정 안 함) |
| CPU / RAM | Intel i7-5820K (6코어 12스레드, PCIe 28레인) / DDR4 16 GB (2채널) |
| 메인보드 | Gigabyte X99-UD4P |
| 냉각 | **사용자 팬 곡선 데몬** (40℃ 30% → 80℃ 이상 100%, NVML). P104 측정 때는 드라이버 기본 곡선 |

**PCIe 링크** — 카드 능력은 Gen3 x16, 실제 폭은 **슬롯이 정한다**(CPU 28레인 = 4 + 8 + 8 + 8).
부하 중 `pcie.link.gen.current` 3 확인.

```
index, name, memory.total [MiB], power.limit [W], pcie.link.gen.max, pcie.link.width.max
0, NVIDIA GeForce GTX 1080 Ti, 11264 MiB, 250.00 W, 3, 16
1, NVIDIA GeForce GTX 1080 Ti, 11264 MiB, 250.00 W, 3, 16
2, NVIDIA GeForce GTX 1080 Ti, 11264 MiB, 250.00 W, 3, 16
3, NVIDIA GeForce GTX 1080 Ti, 11264 MiB, 250.00 W, 3, 16
```

| GPU | 슬롯 | CPU 루트 포트 | 실제 링크 |
|---|---|---|---|
| 0 | PCIE_3 | 00:01.1 | **Gen3 x4** |
| 1 | PCIE_2 | 00:02.0 | Gen3 x8 |
| 2 | PCIE_1 | 00:03.0 (x16 포트를 x8+x8 로 분할) | Gen3 x8 |
| 3 | PCIE_4 | 00:03.2 (같은 포트의 나머지 x8) | Gen3 x8 |

**토폴로지** — `nvidia-smi topo -m`

```
        GPU0  GPU1  GPU2  GPU3  CPU Affinity  NUMA Affinity
GPU0     X    PHB   PHB   PHB   0-11          0
GPU1    PHB    X    PHB   PHB   0-11          0
GPU2    PHB   PHB    X    PHB   0-11          0
GPU3    PHB   PHB   PHB    X    0-11          0

PHB = Connection traversing PCIe as well as a PCIe Host Bridge (typically the CPU)
```

**P2P** — `nvidia-smi topo -p2p r` 전 쌍 `OK`. NVLink·PCIe 스위치 없음.

### 장치 선택 (METHOD v1.5 3절, 비대칭 장치)

이 시스템은 **링크 폭이 다른 장치가 섞여 있다**(x4 하나, x8 셋). v1.5 조항에 따라 장치를 골랐고,
시스템 전체 조건과의 차이를 아래에 표시한다.

| N | **주 측정 장치** | 주 측정 링크 | 보조 측정 장치 (앞에서부터 N장) | 보조 링크 |
|---|---|---|---|---|
| 4 | 0,1,2,3 | x4·x8·x8·x8 (= 시스템 전체) | — | — |
| 3 | **1,2,3** | x8·x8·x8 | 0,1,2 | x4·x8·x8 |
| 2 | **1,3** | x8·x8 | 0,1 | x4·x8 |

- 2장은 1·3 을 골랐다. 둘 다 x8 이고 루트 포트가 다르며, 가장 뜨거운 GPU 2(최상단 슬롯)를 피한다
- **4장은 x4 장치를 뺄 수 없다.** 4장 셀의 링 합산은 x4 링크에 묶인다
- 보조 측정은 버리지 않고 [8절](#8-원시-데이터와-셀-유효성)에 싣는다

## 3. 해석

수치와 계산 과정은 [`gtx1080ti-x4-metrics.ko.md`](gtx1080ti-x4-metrics.ko.md) 에 둔다.
두 플랫폼을 가로지르는 결론은 [`../FINDINGS.ko.md`](../FINDINGS.ko.md) 에 있다.

### 3-1. 텐서 병렬이 프리필·디코드 모두 이긴다 — 기존 결론 확인

4장 기준 텐서/레이어: 웜 pp 343.4 / 149.6 = **2.30배**, tg 28.94 / (유효 레이어 최고 12.45) = **2.32배**.
**세션 손익분기는 없다** — 텐서 4장은 콜드 턴 벽시계(63.8초)도 레이어 2장(98.0초)보다 짧아 첫 턴부터 앞선다.
(콜드 **pp** 만 보면 레이어 4장 551.6 이 텐서 4장 460.6 보다 빠르지만, 콜드 턴은 생성 400 토큰을 포함한다.)

### 3-2. 레이어 분산은 디코드 이득이 0 — 확인

유효 셀은 2장(12.45) 하나지만, 무효 셀의 평균도 12.20(3장)·11.92(4장)로 **장수가 늘어도 빨라지지 않는다.**
웜 pp 도 149.6~152.3 으로 평탄하다. P104·V100 과 같다.

### 3-3. 텐서 프리필이 장수에 따라 늘어난다 — V100 PCIe 와 반대

| 텐서 / off 콜드 pp | 2장 | 3장 | 4장 |
|---|---|---|---|
| P104, Gen1 x4 | 160.2 | 151.5 | 171.4 |
| V100, PCIe Gen3 x16 | 1,140.5 | 961.3 | 887.4 |
| V100, NVLink | 1,188.2 | 1,458.4 | 1,968.2 |
| **1080 Ti, Gen3 x8 (4장만 x4 포함)** | **337.0** | **398.8** | **460.6** |

장수를 늘리면 카드당 계산은 줄고 합산 통신은 늘어난다. 1080 Ti 는 **카드 연산이 V100 보다 훨씬 느리고 링크는
P104 보다 훨씬 넓어** 계산 감소 쪽이 이긴다. 같은 Gen3 PCIe 인데 V100 이 반대인 것은 카드가 빨라 통신 몫이
커지기 때문으로 본다(가설, 분리 측정 안 함).

### 3-4. 텐서 확장 효율

`tg_1` = **12.45 (레이어 / off / 2 로 대용한 환산값)**. 레이어 3·4장이 무효라 METHOD 5절의 "레이어 평균" 대신 유효한 2장 하나를 썼다.

| N | 배수 | 효율 |
|---|---|---|
| 2 | 1.67배 | 83.6% |
| 3 | 2.05배 | 68.5% |
| 4 | 2.32배 | 58.1% |

4장은 x4 장치를 포함한다(보조 측정으로 보면 x4 를 넣은 3장은 tg 가 5% 낮다 — 8절). P104 Gen1 x4 의 4장 효율 57% 와
거의 같다 — 링크가 넓어졌는데 효율이 그대로인 것은 **FINDINGS 5 의 "확장을 가르는 것은 PCIe 대역폭 크기보다 다른
요인"** 과 정합적이다.

### 3-5. 디코드는 대역폭 바운드가 아니다 — 확인

| 셀 | 계산 | 사양(484 GB/s) 대비 |
|---|---|---|
| tensor 4장 | 13,115 MiB / 4 × 28.94 = 99.5 GB/s | **21%** |
| layer 2장 (카드 활성 1/2) | 6.88 GB × 12.45 × 2 = 171 GB/s | 35% |

### 3-6. P104 대비 (4장)

**Gen1 x1 측정이 같은 호스트·드라이버·바이너리**라 카드(와 링크)만 바뀐 비교다. Gen1 x4 측정은 호스트(EPYC 7232 / 32GB)·드라이버·빌드도 달라 단일 변수 비교가 아니다.

| 4장 | P104 Gen1 x1 (같은 호스트) | P104 Gen1 x4 (다른 호스트) | 1080 Ti | 배수 (x1 대비 / x4 대비) |
|---|---|---|---|---|
| 레이어 / off 콜드·웜·tg | 302.6 / 68.6 / 7.40 | 327.3 / 85.3 / 7.82 | 551.6 / 149.6 / 11.92★ | 1.82 / 2.18 / 1.61 · 1.69 / 1.75 / 1.52 |
| 텐서 / off 콜드·웜·tg | 60.7 / 47.2 / 11.16 | 171.4 / 128.8 / 17.89 | 460.6 / 343.4 / 28.94 | **7.59 / 7.28** / 2.59 · **2.69 / 2.67** / 1.62 |

프리필은 링크가 넓어진 텐서 쪽에서 크게 늘고, 디코드는 카드 연산 비율(약 1.8배)에 가깝거나 그보다 작게 는다. Gen1 x1 대비 텐서 배수(7배대)는 대부분 링크 몫이다.

## 7. 이 플랫폼 고유의 한계

- **1장 기준선은 환산값**이다(레이어 / off / 2 = 12.45). 레이어 3·4장이 무효라 METHOD 5절의 평균 대신 한 셀만 썼다
- **N=1 셀 없음** — 모델이 11 GB 에 들어가지 않는다
- **METHOD v1.5 로 측정**(장치 선택 조항). 측정 조건은 v1.0~v1.4 와 같아 같은 표에 놓을 수 있다
- **4장 셀만 x4 링크를 포함한다** — 장수 비교(2·3장 대 4장)에 링크 차이가 섞인다. 보조 측정으로 크기를 추정하면 텐서 웜 pp 6~7%, tg 1~5%
- **냉각 조건이 P104 측정과 다르다**(팬 곡선 데몬). 열 스로틀이 없어서 P104 대비 배수에 냉각 차이가 섞였을 수 있다
- 호스트·드라이버·바이너리는 **P104 Gen1 x1 측정과 같다** — 다만 카드와 함께 링크(Gen1 x1 → Gen3 x4/x8)도 바뀌어 카드 몫과 링크 몫이 섞인다
