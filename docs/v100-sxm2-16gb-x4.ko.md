# NVIDIA V100-SXM2 16GB ×4 — 레이어 병렬 vs 텐서 병렬

측정일 2026-09-14 ~ 09-15. 방법론 **METHOD v1.2** ([`../METHOD.ko.md`](../METHOD.ko.md)).
원시 데이터 [`../results/v100-sxm2-16gb-x4.jsonl`](../results/v100-sxm2-16gb-x4.jsonl).
파생 지표는 별도 문서 [`v100-sxm2-16gb-x4-metrics.ko.md`](v100-sxm2-16gb-x4-metrics.ko.md).

> 측정 조건은 METHOD 에 있다. 여기에는 이 플랫폼의 환경·결과·해석만 적는다.
> 두 플랫폼을 가로지르는 결론은 [`../FINDINGS.ko.md`](../FINDINGS.ko.md) 에 있다.
>
> ⚠️ **영문 [`v100-sxm2-16gb-x4.md`](v100-sxm2-16gb-x4.md) 이 정본이다.**

**이 카드는 SXM2 모듈을 PCIe 로 개조한 물건이다.** 정품 PCIe V100 과 전원부·냉각이
다르고 **NVLink 가 없다.** P104-100 과 같은 메인보드에 꽂아 **같은 바이너리로**
측정했으므로, 두 보고서의 차이는 카드 교체에서 온다.

**P104 에서 얻은 결론 중 무엇이 카드에 따라 달라지는지 확인하는 것이 목표다.**
두 플랫폼은 인터커넥트 대역폭이 약 16배, VRAM 이 2배, 연산이 약 5.7배 차이 난다.
그 결과 **P104 에서 불가능했던 1장 기준선과 `layer / MTP 켬 / 2장` 셀이 여기서
성립했고**, MTP 의 손익 부호와 텐서 확장 효율이 달라졌다.

## 1. 환경

### 하드웨어

| 항목 | 값 |
|---|---|
| GPU | NVIDIA Tesla V100-SXM2-16GB ×4 (GV100, sm_70, Volta) |
| 형태 | **SXM2 → PCIe 개조판. NVLink 없음** |
| VRAM | 16,384 MiB / 장 (유휴 가용 16,145), 65,536 MiB 합계 |
| 메모리 대역폭 | 900 GB/s (HBM2) |
| 전력 상한 | **300W** (측정 중 변경하지 않았다) |
| CPU / RAM | AMD EPYC 7232 8코어 / 32GB |

**PCIe 링크** — `Gen3 x16 이 최대치`다. 유휴 다운시프트가 아니라 하드웨어 천장이며,
부하 중에도 동일하다.

```
index, pcie.link.gen.current, pcie.link.gen.max, pcie.link.width.current, pcie.link.width.max
0, 3, 3, 16, 16
1, 3, 3, 16, 16
2, 3, 3, 16, 16
3, 3, 3, 16, 16
```

**토폴로지** — `nvidia-smi topo -m` 출력 그대로. **P104-100 과 완전히 동일하다**
(같은 메인보드). 토폴로지가 변수에서 빠진다.

```
        GPU0    GPU1    GPU2    GPU3    CPU Affinity    NUMA Affinity   GPU NUMA ID
GPU0     X      NODE    NODE    NODE    0-15            0               N/A
GPU1    NODE     X      NODE    NODE    0-15            0               N/A
GPU2    NODE    NODE     X      PHB     0-15            0               N/A
GPU3    NODE    NODE    PHB      X      0-15            0               N/A

  NODE = Connection traversing PCIe as well as the interconnect between
         PCIe Host Bridges within a NUMA node
  PHB  = Connection traversing PCIe as well as a PCIe Host Bridge (typically the CPU)
```

NVLink 도 PCIe 스위치도 없다. GPU2–GPU3 만 호스트 브리지 하나(PHB)를 거치고
나머지 전 쌍은 브리지를 여럿 거친다(NODE).

## 3. 해석

파생 지표(세션 손익분기, 스케일링 효율, MTP 배치 경제학, 루프라인)의 수치와 계산
과정은 [`v100-sxm2-16gb-x4-metrics.ko.md`](v100-sxm2-16gb-x4-metrics.ko.md) 에 있다.
두 플랫폼을 가로지르는 결론은 [`../FINDINGS.ko.md`](../FINDINGS.ko.md) 에 있다.

### 3-1. 레이어 분산은 여기서도 디코드에 카드를 쓰지 않는다

```
1장 27.71  →  2장 27.97  →  3장 27.78  →  4장 27.29
```

**1장을 실측했으므로 이번에는 추론이 아니다.** 카드를 넷 써서 한 장만큼을 낸다.
P104 의 8.08 → 7.97 → 7.82 와 같은 패턴이다.

프리필은 다르다 — 콜드 pp 가 747.4 → 1,555.5 로 **2.08배**까지 늘고, 웜 pp 는
488.4 / 490.9 / 492.7 / 487.6 으로 **카드 수와 완전히 무관**하다.

### 3-2. 텐서 병렬은 카드 수에 비례해 빨라진다 — 양쪽 플랫폼 모두

```
2장 41.64  →  3장 42.79  →  4장 46.62      +12.0%
```

P104 도 13.06 → 14.14 → 17.89 로 **+37.0%** 늘었다. **상대 증가폭은 오히려
P104 가 크다.** 확장 효율의 대조는 metrics 문서와 FINDINGS 5 에 있다.

### 3-3. 콜드는 레이어, 웜은 텐서 — 방향이 유지된다

```
콜드   layer 1,555.5  대  tensor 887.4    =  레이어 1.75배
웜     tensor 594.1   대  layer 487.6     =  텐서 1.22배
```

P104 는 1.91배 / 1.51배였다. **방향은 같고 크기만 줄었다.**

### 3-4. MTP 가 레이어 모드에서 이득으로 돌아섰다

```
P104   layer 4장   7.82 → 6.54    −16.4%   손해
V100   layer 4장  27.29 → 28.25    +3.5%   이득
```

**수락률은 29.9% → 32.0% 로 거의 그대로다.** 바뀐 것은 배치 검증의 비용 배수이며,
계산은 metrics 문서에 있다. 원리는 [FINDINGS 4](../FINDINGS.ko.md) 를 볼 것.

**단, 텐서 모드에서는 여전히 손해다** — 3장 −12.1%, 2장 −5.9%. **같은 카드에서
분할 방식에 따라 부호가 갈린다.**

## 4. MTP 는 평균보다 분산이 문제다

웜 4턴의 `tg` 편차다.

| 셀 | 웜 4턴 tg | 편차 |
|---|---|---|
| layer / MTP off / 4장 | 27.75 / 26.53 / 27.71 / 27.19 | 4.6% |
| layer / MTP on / 4장 | 26.61 / 27.26 / 31.02 / 28.10 | **16.6%** |
| layer / MTP on / 2장 | 28.06 / 27.80 / 31.78 / 30.09 | **14.3%** |
| tensor / MTP off / 4장 | 46.48 / 46.62 / 46.63 / 46.74 | **0.6%** |
| tensor / MTP on / 3장 | 38.72 / 36.19 / 35.61 / 39.87 | **12.0%** |
| tensor / MTP on / 2장 | 35.77 / 39.95 / 40.53 / 40.41 | **13.3%** |

**MTP off 텐서 셀이 0.6% 로 가장 안정적이고, MTP on 셀은 12~17% 로 출렁인다.**
METHOD 4절에 따라 MTP on 셀에는 5% 기준을 적용하지 않으며, **편차 자체를 결과로
보고한다.**

평균이 이득인 `layer / MTP on` 조차 편차가 14~17% 다. **응답 시간이 들쭉날쭉하면
체감 품질은 평균이 시사하는 것보다 나쁘다.**

## 5. Xid 79 — `텐서 + MTP + 4장`

**두 번 모두 죽었다.** 1차는 12셀 매트릭스 실행 중, 2차는 전력 상한을 250W 로 낮춰
같은 셀만 다시 돌렸을 때다. 2차에서는 GPU 0·2·3 이 동시에 손실됐고, 둘 다 재부팅으로
완전히 복구됐다.

```
NVRM: Xid (PCI:0000:01:00): 79, GPU has fallen off the bus.
```

**4장을 쓰는 다른 세 셀은 모두 완주했다**(`layer-nomtp-4`, `layer-mtp-4`,
`tensor-nomtp-4`). **같은 조합이 P104 에서는 14.82 t/s 로 완주했다.**

배제된 원인은 과열(크래시 셀 최고 50도), 지속 전력 초과(상한의 60%, 250W 로 낮춰도
재현), ECC(Retired Pages 0), 카드 개별 결함(3장 동시 손실)이다. 남은 가설은
**PCIe 트랜잭션 빈도**이며 **미확정**이다. 전말과 근거는
[FINDINGS 7](../FINDINGS.ko.md) 에 있다.

**실무적으로는 피하면 그만이다** — 최고 성능 구성인 `tensor-nomtp-4`(46.62 t/s)에는
MTP 가 없고, MTP 는 텐서 모드에서 어차피 손해다(2-5절).

## 6. 이 플랫폼 고유의 한계

1. **`tensor-mtp-4` 는 영구 공백이다.** 텐서 모드의 MTP 효과를 4장으로 외삽하지 말 것
2. **열·전력 스로틀을 집계하지 못했다.** METHOD v1.1 하네스로 측정했다. 온도만
   남아 있고, 재측정은 크래시 셀을 다시 밟는 일이라 하지 않았다
3. **`tensor-mtp` 3·2장은 재측정값이다.** 최초 측정치는 오염됐다(7절). 두 값
   모두 원시 데이터에 보존돼 있다
4. **이 카드는 SXM2 → PCIe 개조판이다.** 정품 PCIe V100 과 전원부·냉각이 다르고
   NVLink 가 없다. 정품 카드로 옮겨갈 때 그대로 적용되지 않을 수 있다
5. **1장에서 layer 와 tensor 가 0.97% 다른 이유를 확인하지 않았다.** 실행 순서에
   따른 온도 차로 추정만 했다
6. **Q6_K 대조를 재지 않았다.** P104 보고서의 양자화 관련 결론은 이 플랫폼에서
   확인되지 않았다

**오염된 원본과 재측정값을 함께 싣는다.** 판정의 근거를 독자가 직접 확인할 수
있어야 하기 때문이다. 크래시가 이후 셀에 영향을 남긴다는 사례이기도 하다
(METHOD 4절).

원시 데이터의 모든 줄에 **`validity` 필드**가 있어 파일만 보고도 구분된다.
오염된 줄과 그것을 대체하는 줄은 **파일에서 나란히 놓여** 값을 직접 비교할 수 있다.

| `validity` | 뜻 |
|---|---|
| `ok` | 정상 |
| `failed` | 결과를 내지 못함 |
| `contaminated` | 크래시 직후 측정. **대체됐으나 근거로 보존** |
| `remeasured` | 오염 셀의 대체 측정 |

각 줄의 `note` 필드에 그 판정의 근거가 함께 들어 있다.
