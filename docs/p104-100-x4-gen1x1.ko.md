# NVIDIA P104-100 8GB ×4, PCIe Gen1 x1 — 레이어 병렬 vs 텐서 병렬

측정일 2026-10-01~02. 방법론 **METHOD v1.3** ([`../METHOD.ko.md`](../METHOD.ko.md)).
원시 데이터 [`../results/p104-100-x4-gen1x1.jsonl`](../results/p104-100-x4-gen1x1.jsonl).
파생 지표는 별도 문서 [`p104-100-x4-gen1x1-metrics.ko.md`](p104-100-x4-gen1x1-metrics.ko.md).

> 측정 조건은 METHOD 에 있다. 여기에는 이 플랫폼의 환경·결과·해석만 적는다.
> 플랫폼을 가로지르는 결론은 [`../FINDINGS.ko.md`](../FINDINGS.ko.md) 에 있다.
>
> ⚠️ **영문 [`p104-100-x4-gen1x1.md`](p104-100-x4-gen1x1.md) 이 정본이다.**

**[`p104-100-x4.ko.md`](p104-100-x4.ko.md) 와 같은 카드 모델을 PCIe 규격상 가장 느린
링크에 올렸다.** 카드가 x1 채굴용 라이저에 꽂혀 있어 모든 링크가 Gen1 x1(약
250 MB/s)로 동작한다 — 첫 P104 측정의 Gen1 x4 의 4분의 1이다. 모델 파일과 llama.cpp
커밋이 그 측정과 같아서, 이 저장소에서 같은 카드로 대역폭만 비교하는 데 가장 가까운
측정이다. 다만 **단일 변수 실험은 아니다** — 호스트 CPU 와 RAM 도 함께 바뀌었다(1절).

**확인한 것과 뒤집은 것.** 레이어 분산은 여전히 디코드 속도를 사지 못하고, 디코드
1위는 여전히 텐서 병렬이다 — 4장에서 레이어 분산의 1.51배로, 2.29배에서 줄었다.
바뀐 것은 프리필에 달린 모든 것이다. 웜 프리필의 우열이 뒤집히고, 세션에서 텐서
4장이 레이어 4장을 앞지르기까지 Gen1 x4 의 1.2턴 대신 21.5턴이 걸린다.

## 1. 환경

### 하드웨어

| 항목 | 값 |
|---|---|
| GPU | NVIDIA P104-100 8GB ×6 장착, **셀당 최대 4장 사용** (GP104, sm_61, Pascal) |
| VRAM | 카드당 8,192 MiB, 사용 가능 8,109 MiB (83 MiB 예약) |
| 메모리 대역폭 | 약 320 GB/s (GDDR5X 256-bit) |
| 전력 상한 | 180W (측정 중 변경 없음) |
| CPU / RAM | **Intel Core i7-5820K**, 6코어 12스레드 / **16GB** DDR4 |
| 메인보드 | Gigabyte GA-X99-UD4P |

첫 P104 측정은 AMD EPYC 7232 / 32GB 였다. **링크와 함께 호스트가 바뀌었다**
([관련 고지 11)](../FINDINGS.ko.md#관련-고지)). 이전 보고서에 카드 UUID 를 기록하지
않아 같은 실물 카드인지는 보일 수 없다.

**PCIe 링크** — **모든 카드가 Gen1 x1 로 동작한다.** `width.max` 가 4 인 것은 카드가
지원하는 폭이고, 1 로 묶는 것은 x1 라이저다. 부하 중에도 같음을 확인했다.

```
index, pcie.link.gen.current, pcie.link.gen.max, pcie.link.width.current, pcie.link.width.max
0, 1, 1, 1, 4
1, 1, 1, 1, 4
2, 1, 1, 1, 4
3, 1, 1, 1, 4
4, 1, 1, 1, 4
5, 1, 1, 1, 4
```

**토폴로지** — `nvidia-smi topo -m` 원문. 6장 모두 같은 호스트 브리지 아래에 있다.

```
        GPU0    GPU1    GPU2    GPU3    GPU4    GPU5    CPU Affinity    NUMA Affinity   GPU NUMA ID
GPU0     X      PHB     PHB     PHB     PHB     PHB     0-11            0               N/A
GPU1    PHB      X      PHB     PHB     PHB     PHB     0-11            0               N/A
GPU2    PHB     PHB      X      PHB     PHB     PHB     0-11            0               N/A
GPU3    PHB     PHB     PHB      X      PHB     PHB     0-11            0               N/A
GPU4    PHB     PHB     PHB     PHB      X      PHB     0-11            0               N/A
GPU5    PHB     PHB     PHB     PHB     PHB      X      0-11            0               N/A

  X    = Self
  PHB  = Connection traversing PCIe as well as a PCIe Host Bridge (typically the CPU)
```

**P2P** — `nvidia-smi topo -p2p r` 결과 모든 쌍이 `OK`.

## 2. 결과

- **프리필 (pp)** = 프롬프트를 읽는 속도. 응답의 `prompt_per_second`
- **생성 (tg)** = 최종 출력 토큰 속도. 응답의 `predicted_per_second`
  (드래프트 토큰이 아니라 **확정 출력** 기준이다. 전 턴에서 `predicted_n = 400`)
- 콜드는 1회, 웜은 4턴 평균
- **비율(%)** 은 지표마다 **그 지표의 최저 셀**을 100 으로 둔 값이다

| 지표 | 기준 셀 (100%) | 값 |
|---|---|---|
| 콜드 pp | tensor / MTP 켬 / 4장 | 55.3 t/s |
| 웜 pp | tensor / MTP 켬 / 4장 | 39.2 t/s |
| tg | layer / MTP 켬 / 4장 | 6.18 t/s |

⚠️ **11셀 중 9셀은 서로 다른 GPU 에서 두 셀씩 동시에 측정했다.** 같은 셀을 먼저 단독과
동시로 각각 돌려 차이가 2.1% 이내임을 확인했다(5-1절). METHOD v1.3 이 이를 허용한다
([관련 고지 10)](../FINDINGS.ko.md#관련-고지)).

**읽을 것 셋.**

1. **상위 3개는 여전히 MTP 없는 텐서 병렬이다** — Gen1 x4 와 V100 의 1위와 같다. 그러나
   분할 방식이 더 이상 깔끔하게 갈리지 않는다. Gen1 x4 에서는 텐서 6셀이 레이어 5셀을
   모두 이겼지만, 여기서는 **MTP 를 켠 텐서가 레이어 사이에 섞이고**
   `tensor / MTP 켬 / 2장` 은 9위로 내려간다.
2. **MTP 가 텐서 병렬에 주는 손해가 Gen1 x4 보다 훨씬 크다.** 텐서 4장에서 MTP 를 켜면
   여기서는 31%, Gen1 x4 에서는 17% 를 잃는다(3-5절).
3. **콜드 pp 순위가 tg 순위를 뒤집은 모양이고, 그 정도가 이전보다 심하다.** 레이어
   분산이 콜드 프리필에서 최대 548% 로 앞서는 동안 tg 1위는 110% 에 그친다(3-2절).

## 3. 해석

수치와 계산 근거는 [`p104-100-x4-gen1x1-metrics.ko.md`](p104-100-x4-gen1x1-metrics.ko.md)
에 있다. 아래에 인용한 Gen1 x4 값은 [`p104-100-x4.ko.md`](p104-100-x4.ko.md) 의 것이다.

### 3-1. 레이어 분산은 디코드에서 카드를 쓰지 않는다 — Gen1 x1 에서도 같다

| N | 2 | 3 | 4 |
|---|---|---|---|
| tg | 7.61 | 7.62 | 7.40 |

Gen1 x4, V100 과 마찬가지로 3% 안에서 평탄하다. 한 시점에 한 장만 계산하므로 링크가
좁아져도 늦출 것이 별로 없다 — **레이어 분산의 디코드는 Gen1 x4 대비 4~6% 만 잃었다.**

### 3-2. 콜드 프리필은 여전히 레이어가 앞서고 — 이제 웜 프리필도 그렇다

| | 콜드 (23,037tok) | 웜 (637~790tok) |
|---|---|---|
| layer 4장 | **302.6** | **68.6** |
| tensor 4장 | 60.7 | 47.2 |

| 배수 | Gen1 x4 | **Gen1 x1** |
|---|---|---|
| 콜드 — 레이어 우세 | 1.91배 | **4.99배** |
| 웜 | 텐서 우세 1.51배 | **레이어 우세 1.45배** |

**앞의 두 플랫폼 모두에서 성립했던 결론을 뒤집는다.** Gen1 x4 와 V100 에서는 웜
프리필이 텐서 병렬에 유리했다. Gen1 x1 에서는 배치마다 도는 all-reduce 비용이 일을
나눠서 얻는 이득보다 커서, 700토큰짜리 웜 프롬프트에서도 텐서가 진다.

### 3-3. 웜 턴은 여전히 생성이 지배한다 — 이전보다는 덜하다

| | layer 4장 | tensor 4장 |
|---|---|---|
| 프리필 | 10.7초 (17%) | 15.5초 (30%) |
| 생성 | 54.0초 (83%) | 35.8초 (70%) |

Gen1 x4 에서는 같은 배분이 레이어 14% / 86%, 텐서 20% / 80% 였다. **웜 프리필이 텐서
병렬 턴의 3분의 1 가까이로 커져서**, 텐서가 생성에서 얻는 이득을 일부 돌려준다.

**Gen1 x1 이 아픈 곳은 콜드 턴이다.** 23k 토큰을 읽는 데 레이어 분산은 76초, **텐서
병렬은 380초**가 걸린다. 텐서 병렬은 웜 턴마다 이기지만(51.4초 대 64.7초) 그 5분의
적자를 갚는 데 **웜 21.5턴**이 걸린다. Gen1 x4 에서는 1.2턴이었다(metrics 1절).

### 3-4. 디코드는 여전히 대역폭 바운드가 아니다 — 링크가 활용률을 더 낮춘다

| 구성 | 실효 대역폭 | 사양 대비 | Gen1 x4 |
|---|---|---|---|
| layer 4장 | 102 GB/s | 32% | 34% |
| tensor 4장 | 38 GB/s | **12%** | 19% |

레이어 분산은 거의 그대로다. 텐서 병렬은 메모리 대역폭을 이전보다 **덜** 쓴다.
토큰마다 링크를 기다리는 시간이 늘었기 때문이다. 이 카드의 디코드는 Gen1 x4 에서도
메모리 바운드가 아니었고, 여기서는 그보다 더 멀다.

### 3-5. MTP — 판정은 같고, 텐서 병렬이 더 많이 낸다

| | layer 4 | tensor 4 | tensor 3 | tensor 2 |
|---|---|---|---|---|
| **비용 배수** | **2.26** | **2.90** | 2.86 | 2.72 |
| Gen1 x4 비용 배수 | 2.25 | 2.42 | — | — |
| 손익분기 수락률 | 42.4% | **63.9%** | 62.6% | 57.9% |
| 실측 수락률 | 29.9% | 33.1% | 36.2% | 29.1% |
| 실측 손익 | −16.4% | **−30.6%** | −23.0% | −31.4% |

**레이어 분산은 Gen1 x4 와 같은 배수를 낸다**(2.26 대 2.25) — 검증 배치가 링크를 더
자주 건너지 않기 때문이다. **텐서 병렬의 배수는 2.42 → 2.90 으로 오른다.** 배치 4의
검증이 이미 병목인 링크 위에 all-reduce 트래픽을 더하기 때문이다. 수락률은 그대로라
(모델·픽스처·시드가 같다) 늘어난 손해는 전부 비용 쪽에서 온다.

**비용 모델은 여전히 결과를 예측한다** — 다섯 셀 중 넷이 1%p 안에 든다. `tensor-mtp-3`
만 4.4%p 벗어나는데, 웜 편차도 가장 큰 셀이다(4절).

## 5. 동시 측정과 실패

### 5-1. 동시 측정

6장이면 겹치지 않는 GPU 에서 두 셀을 동시에 돌릴 수 있다. **매트릭스를 그렇게 돌리기
전에, 같은 셀을 단독과 동시로 각각 기동해 차이를 확인했다.**

| 셀 | 지표 | 단독 | 동시 | 차이 |
|---|---|---|---|---|
| layer-nomtp-4 | 콜드 pp | 302.5 | 302.6 | +0.0% |
| | 웜 pp | 68.6 | 68.6 | 0.0% |
| | tg | 7.52 | 7.40 | −1.7% |
| layer-nomtp-2 | 콜드 pp | 206.8 | 202.5 | **−2.1%** |
| | 웜 pp | 70.7 | 70.2 | −0.7% |
| | tg | 7.68 | 7.61 | −0.9% |
| tensor-nomtp-4 | 콜드 pp | 60.7 | 60.7 | −0.1% |
| | 웜 pp | 47.2 | 47.2 | −0.1% |
| | tg | 11.19 | 11.16 | −0.3% |

**최대 차이는 2.1% 다.** 호스트 브리지를 공유하는데도 경합이 없는 이유는, 카드마다의
x1 링크가 먼저 포화돼 상위에서 다툴 여유가 없기 때문으로 본다. 측정이 아니라 추정이다.

어떤 셀이 어느 GPU 에서 겹쳤는지:

| 함께 돈 셀 | GPU |
|---|---|
| layer-nomtp-4 ‖ layer-nomtp-2 | 0-3 ‖ 4-5 |
| tensor-nomtp-4 ‖ tensor-nomtp-2 | 0-3 ‖ 4-5 |
| tensor-mtp-4 ‖ tensor-mtp-2 | 0-3 ‖ 4-5 |
| layer-mtp-3 ‖ tensor-mtp-3 | 0-2 ‖ 3-5 |
| tensor-nomtp-3 ‖ (layer-mtp-2 로딩 시도, 실패) | 0-2 ‖ 4-5, 처음 약 5분만 |
| layer-nomtp-3, layer-mtp-4 | 단독 |

보고값은 동시 측정본이고, 단독 측정본은 원시 데이터에 `validity: side` 로 남겼다.

### 5-2. `layer-mtp-2` — 로딩 중 메모리 부족

```
allocating 268.06 MiB on device 1: cudaMalloc failed: out of memory
failed to allocate compute pp buffers
```

| 원인 | 판정 |
|---|---|
| llama.cpp 빌드 차이 | **배제.** 이 셀이 완주한 Gen1 x4 와 같은 커밋 |
| 모델 파일 차이 | **배제.** sha256 동일 |
| 동시 측정 셀의 VRAM 점유 | **배제.** 이 셀은 GPU 4,5 에서, 동시 셀은 0-2 에서 돌았다 |

남은 차이는 CUDA 아키텍처 목록(`61` 대 `61;70`)과 드라이버(580.178 대 580.173)다.
**둘 다 검증하지 않았고, 원인은 미확정이다.** 실무상 손해는 없다 — 레이어 분산 + MTP 는
이 카드에서 장수와 무관하게 가장 느린 구성이다.

## 6. 이 플랫폼 고유의 한계

- **Gen1 x4 와의 단일 변수 비교가 아니다.** 링크와 함께 호스트 CPU(EPYC 7232 →
  i7-5820K), RAM(32GB → 16GB), 드라이버, 아키텍처 목록이 바뀌었다. 프리필과 디코드는
  GPU 바운드이고 CPU 는 토큰화와 샘플링만 맡으므로 링크를 주요인으로 보지만,
  **분리해서 확인하지는 않았다**
- **1장 기준선은 환산값이다.** Gen1 x4 와 같다
- **`layer-mtp-2` 가 빠져 있다**(5-2절)
- **9셀은 동시에 측정했다**(5-1절)
- **카드가 x1 라이저에 꽂혀 있어** 전기적 경로도 길다. 측정 중 PCIe 오류 카운터(AER)는
  확인하지 않았다
- 텐서 병렬은 N 이 바뀌면 출력이 달라진다(METHOD 6-2)
