## 1. 세션 소요와 손익분기

세션은 콜드 1턴과 웜 N턴이다.

| 구성 | Gen1 x1 | Gen1 x4 |
|---|---|---|
| layer / 없음 / 4장 | 128.8 + **64.7N** 초 | 119.8 + 59.7N 초 |
| layer / 없음 / 2장 | 166.1 + **62.9N** 초 | 157.7 + 57.9N 초 |
| tensor / 없음 / 4장 | 415.5 + **51.4N** 초 | 156.6 + 28.1N 초 |
| tensor / 없음 / 2장 | 398.1 + **56.8N** 초 | 174.2 + 36.9N 초 |

```
손익분기 N = (콜드_A − 콜드_B) / (웜_B − 웜_A)
```

| 손익분기 | Gen1 x1 | Gen1 x4 |
|---|---|---|
| tensor 4장 > layer 4장 | **21.5**턴 | 1.2 |
| tensor 2장 > layer 4장 | **34.0**턴 | 2.4 |

**텐서 병렬은 웜 턴마다 여전히 이긴다** — 51.4초 대 64.7초. 바뀐 것은 빨리 이기지
못한다는 점이다. 콜드 턴에서 **286.7초 뒤처지고**(Gen1 x4 에서는 36.8초), 23k 토큰
콜드 프리필이 텐서 병렬로 380초, 레이어 분산으로 76초 걸리는 반면 그것을 갚을 턴당
이득은 31.6초에서 13.3초로 줄었다.

Gen1 x4 에서는 "텐서 2장이 레이어 4장을 세 번째 메시지에서 앞지른다"였다. **Gen1 x1
에서는 34번째 메시지다.** 긴 대화 하나를 이어가는 워크로드라면 여전히 이득이고, 그보다
짧으면 레이어 분산이 앞선다.

## 2. 텐서 병렬 스케일링 효율

```
효율(N) = (tg_tensor(N) / tg_1) / N
```

⚠️ **`tg_1` 은 환산값이다.** 모델이 8GB 카드 한 장에 들어가지 않으므로, Gen1 x4 와
마찬가지로 같은 N 의 레이어 분산 `tg` 를 대용한다
([관련 고지 2)](../FINDINGS.ko.md#관련-고지)).

| N | tensor tg | layer tg (=1장) | 배수 | **효율** | Gen1 x4 효율 |
|---|---|---|---|---|---|
| 2 | 9.58 | 7.61 | 1.26배 | **63%** | 81% |
| 3 | 10.70 | 7.62 | 1.40배 | **47%** | 59% |
| 4 | 11.16 | 7.40 | 1.51배 | **38%** | 57% |

| | Gen1 x1 | Gen1 x4 |
|---|---|---|
| tensor, 2 → 4장 | **1.16배** | 1.37배 |

**링크를 4분의 1로 줄이자 모든 N 에서 효율이 떨어지고, 카드를 더해도 덜 는다.** 이
저장소에서 카드는 그대로 두고 링크만 바뀐 첫 비교다.

### 2-1. V100 결과와의 관계

[FINDINGS 5](../FINDINGS.ko.md) 는 16배 빠른 링크(P104 Gen1 x4 → V100 Gen3 x16)가
텐서 확장을 **개선하지 못했음**을 보였다. 이 플랫폼은 같은 카드에서 4배 느린 링크가
확장을 **악화시킴**을 보인다. 둘은 모순되지 않는다 — **Gen1 x4 이상에서는 대역폭이
확장의 제약이 아니지만, 그 아래에서는 제약 중 하나가 된다.** x1 과 x4 사이 어디서
그렇게 바뀌는지는 재지 않았다.

## 3. MTP 배치 경제학

```
스텝 수         = n_predict − draft_n_accepted
스텝당 비용     = predicted_ms(MTP 켬) / 스텝 수
토큰당 비용     = predicted_ms(MTP 끔) / n_predict
비용 배수       = 스텝당 비용 / 토큰당 비용
스텝당 산출     = n_predict / 스텝 수
```

| | layer 4 | layer 3 | tensor 4 | tensor 3 | tensor 2 |
|---|---|---|---|---|---|
| MTP 끔, 토큰당 | 134.9 ms | 130.9 ms | 89.4 ms | 93.2 ms | 104.1 ms |
| MTP 켬, **스텝당** | 304.8 ms | 302.1 ms | 259.6 ms | 266.8 ms | 283.4 ms |
| **비용 배수** | **2.26** | **2.31** | **2.90** | **2.86** | **2.72** |
| 드래프트 길이 | 2.97 | 2.97 | 2.98 | 2.98 | 2.97 |
| 스텝당 산출 | 1.89 | 1.89 | 1.99 | 2.08 | 1.86 |
| **손익분기 수락률** | **42.4%** | **44.0%** | **63.9%** | **62.6%** | **57.9%** |
| 실측 수락률 | 29.9% | 29.9% | 33.1% | 36.2% | 29.1% |
| **예측 손익** | −16.4% | −18.1% | −31.6% | −27.4% | −31.5% |
| **실측 손익** | **−16.4%** | **−18.1%** | **−30.6%** | **−23.0%** | **−31.4%** |

**다섯 셀 중 넷에서 예측과 실측이 1%p 안에 든다.** `tensor-mtp-3` 만 4.4%p 벗어나는데,
웜 편차가 66.9% 로 이번 측정에서 가장 크다.

### 3-1. Gen1 x4 대조

| 비용 배수 | Gen1 x1 | Gen1 x4 |
|---|---|---|
| layer 4 | 2.26 | 2.25 |
| tensor 4 | **2.90** | 2.42 |

**레이어 분산은 같은 배수를 낸다** — 배치 4를 검증해도 링크로 더 보내는 것이 없다.
**텐서 병렬은 20% 더 낸다.** 검증 배치가 이미 병목인 링크 위에 all-reduce 트래픽을
더하기 때문이다. 텐서 4장의 손익분기선이 47.8% 에서 63.9% 로 올라가는 동안 수락률은
33.1% 그대로다.

## 4. 루프라인

```
실효 대역폭 = 카드가 읽는 바이트 / 그 카드가 쓰는 시간
```

모델은 12.81 GiB 이고 토큰마다 한 번 읽는다. 사양 대역폭은 약 320 GB/s 다.

| 구성 | 계산 | 실효 대역폭 | 사양 대비 | Gen1 x4 |
|---|---|---|---|---|
| layer 4장 | 카드당 3.20 GiB / 33.8 ms (135 ms 중 1/4 만 가동) | 102 GB/s | **32%** | 34% |
| tensor 4장 | 카드당 3.20 GiB / 89.6 ms (넷이 동시에) | 38 GB/s | **12%** | 19% |
| tensor 2장 | 카드당 6.41 GiB / 104.3 ms | 66 GB/s | 21% | 28% |

**레이어 분산은 메모리 대역폭을 이전처럼 쓰고, 텐서 병렬은 덜 쓴다.** 토큰마다 링크를
기다리는 시간이 늘어 카드가 가중치를 더 천천히 읽는다. 디코드는 Gen1 x4 에서도 메모리
바운드가 아니었고, 여기서는 더 멀다.

## 5. 링크에 대한 민감도 (Gen1 x4 → x1)

두 링크에서 모두 잰 셀 전부다.

| 셀 | 콜드 pp | 웜 pp | tg |
|---|---|---|---|
| layer-nomtp-4 | −7.5% | −19.6% | −5.4% |
| layer-nomtp-3 | −5.2% | −18.2% | −4.4% |
| layer-nomtp-2 | −4.8% | −19.2% | −5.8% |
| layer-mtp-4 | −11.9% | −26.4% | −5.5% |
| layer-mtp-3 | −9.1% | −26.2% | −6.1% |
| **tensor-nomtp-4** | **−64.6%** | **−63.4%** | **−37.6%** |
| tensor-nomtp-3 | −57.7% | −55.8% | −24.3% |
| tensor-nomtp-2 | −59.7% | −58.3% | −26.6% |
| tensor-mtp-4 | −64.8% | −63.4% | −47.8% |
| tensor-mtp-3 | −59.0% | −57.5% | −38.3% |
| tensor-mtp-2 | −60.5% | −59.4% | −37.3% |

**레이어 분산은 디코드 4~6%, 콜드 프리필 5~12% 를 잃고, 텐서 병렬은 디코드 24~48%,
프리필 58~65% 를 잃는다.** 레이어 분산은 카드 경계마다 활성값 하나를 넘기고, 텐서
병렬은 토큰마다 층마다 all-reduce 를 한다.

**레이어 분산의 웜 프리필은 예외다** — 18~26% 로, 콜드 프리필 손해의 세 배다. 짧은
프롬프트는 마이크로배치가 한둘이라 카드 경계의 전송이 연산 뒤에 숨지 못하는 것이 유력한
이유로 보인다. **검증하지는 않았다.**

**그래도 4장에서 텐서 병렬의 디코드가 레이어 분산의 1.51배다**(11.16 대 7.40). Gen1 x4
에서는 2.29배였다. 링크는 텐서 병렬의 우위 대부분을 가져갔지만 우위 자체를 가져가지는
못했다.
