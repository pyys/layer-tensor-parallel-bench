# NVIDIA P104-100 8GB x4 at PCIe Gen1 x1 — layer split vs tensor parallelism

Measured 2026-10-01~02. Methodology **METHOD v1.3** ([`../METHOD.md`](../METHOD.md)).
Raw data [`../results/p104-100-x4-gen1x1.jsonl`](../results/p104-100-x4-gen1x1.jsonl).
Derived metrics live in [`p104-100-x4-gen1x1-metrics.md`](p104-100-x4-gen1x1-metrics.md).

> Measurement conditions are in METHOD. This document holds only **this platform's
> environment, results and interpretation.**
> Conclusions that span platforms are in [`../FINDINGS.md`](../FINDINGS.md).

**The same card model as [`p104-100-x4.md`](p104-100-x4.md), on the slowest PCIe link
there is.** The cards now sit on x1 mining risers, so every link runs at Gen1 x1
(~250 MB/s) — a quarter of the Gen1 x4 the first P104 run had. The model file and the
llama.cpp commit are identical to that run, which makes this the closest thing in the
repository to a same-card bandwidth comparison. It is still **not a single-variable
experiment** — the host CPU and RAM changed as well (section 1).

**What it confirms and what it overturns.** Layer split still buys no decode speed, and
tensor parallelism still decodes fastest — 1.51x layer split at four cards, down from
2.29x. What changes is everything that depends on prefill: the warm prefill ranking
reverses, and tensor 4 cards needs 21.5 warm turns to overtake layer 4 cards in a
session, against 1.2 at Gen1 x4.

## 2. Results

- **Prefill (pp)** = how fast the prompt is read. `prompt_per_second`
- **Generation (tg)** = final output token rate. `predicted_per_second`,
  on confirmed output rather than drafts — `predicted_n` is 400 on every turn
- Cold is one run, warm is the mean of four turns
- **Percentages** are relative to **the slowest cell for that metric**, which is 100

| Metric | Baseline cell (100%) | Value |
|---|---|---|
| Cold pp | tensor / MTP on / 4 cards | 55.3 t/s |
| Warm pp | tensor / MTP on / 4 cards | 39.2 t/s |
| tg | layer / MTP on / 4 cards | 6.18 t/s |

⚠️ **Nine of the eleven cells were measured two at a time on separate GPUs.** The same
cell was first run alone and concurrently, and the difference was within 2.1%
(section 5-1). METHOD v1.3 permits this

## 3. Interpretation

Figures and the calculations behind them are in
[`p104-100-x4-gen1x1-metrics.md`](p104-100-x4-gen1x1-metrics.md). The Gen1 x4 values
quoted below are from [`p104-100-x4.md`](p104-100-x4.md).

### 3-1. Layer split does not use the cards during decode — same at Gen1 x1

| N | 2 | 3 | 4 |
|---|---|---|---|
| tg | 7.61 | 7.62 | 7.40 |

Flat within 3%, as at Gen1 x4 and on V100. Only one card computes at a time, so a
narrower link has little to slow down — **layer-split decode lost only 4~6% against
Gen1 x4.**

### 3-2. Cold prefill still favours layer split — warm prefill now does too

| | Cold (23,037 tok) | Warm (637~790 tok) |
|---|---|---|
| layer 4 | **302.6** | **68.6** |
| tensor 4 | 60.7 | 47.2 |

| Ratio | Gen1 x4 | **Gen1 x1** |
|---|---|---|
| Cold — layer ahead | 1.91x | **4.99x** |
| Warm | tensor ahead 1.51x | **layer ahead 1.45x** |

**This overturns a conclusion that held on both earlier platforms.** At Gen1 x4 and on
V100 warm prefill favoured tensor parallelism. At Gen1 x1 the all-reduce per batch
costs more than tensor parallelism gains from splitting the work, even for a
700-token warm prompt.

### 3-3. Generation still dominates a warm turn — less than before

| | layer 4 | tensor 4 |
|---|---|---|
| Prefill | 10.7s (17%) | 15.5s (30%) |
| Generation | 54.0s (83%) | 35.8s (70%) |

At Gen1 x4 the same split was 14% / 86% for layer and 20% / 80% for tensor. **Warm
prefill grows into a third of a tensor-parallel turn**, so the advantage tensor
parallelism has in generation is partly given back.

**The cold turn is where Gen1 x1 bites.** Reading 23k tokens takes 76s under layer
split and **380s under tensor parallelism**. Tensor parallelism wins every warm turn
(51.4s against 64.7s) but needs **21.5 warm turns** to repay that five-minute deficit,
against 1.2 at Gen1 x4 (metrics section 1).

### 3-4. Decode is still not bandwidth bound — the link pulls utilization down further

| Configuration | Effective bandwidth | Against spec | Gen1 x4 |
|---|---|---|---|
| layer 4 | 102 GB/s | 32% | 34% |
| tensor 4 | 38 GB/s | **12%** | 19% |

Layer split barely moves. Tensor parallelism uses **less** memory bandwidth than
before, because more of each token's time is spent waiting on the link. Decode on this
card was not memory bound at Gen1 x4 and is less so here.

### 3-5. MTP — same verdict, and tensor parallelism pays more for it

| | layer 4 | tensor 4 | tensor 3 | tensor 2 |
|---|---|---|---|---|
| **Cost multiple** | **2.26** | **2.90** | 2.86 | 2.72 |
| Gen1 x4 cost multiple | 2.25 | 2.42 | — | — |
| Break-even acceptance | 42.4% | **63.9%** | 62.6% | 57.9% |
| Measured acceptance | 29.9% | 33.1% | 36.2% | 29.1% |
| Measured change | −16.4% | **−30.6%** | −23.0% | −31.4% |

**Layer split pays the same multiple as at Gen1 x4** (2.26 against 2.25) — its
verification batch does not cross the link more often. **Tensor parallelism's multiple
rises from 2.42 to 2.90**, because verifying a batch of four adds all-reduce traffic on
top of a link that is already the bottleneck. Acceptance is unchanged (the model,
fixture and seed are the same), so the larger loss comes entirely from the cost side.

**The cost model still predicts the result** — within 1 percentage point in four of
five cells. `tensor-mtp-3` misses by 4.4 points; it is also the cell with the widest
warm spread (section 4).

### 5-1. Concurrent measurement

Six cards allow two cells at a time on disjoint GPUs. **Before running the matrix that
way, the same cell was run alone and concurrently, and the difference was checked.**

| Cell | Metric | Alone | Concurrent | Difference |
|---|---|---|---|---|
| layer-nomtp-4 | cold pp | 302.5 | 302.6 | +0.0% |
| | warm pp | 68.6 | 68.6 | 0.0% |
| | tg | 7.52 | 7.40 | −1.7% |
| layer-nomtp-2 | cold pp | 206.8 | 202.5 | **−2.1%** |
| | warm pp | 70.7 | 70.2 | −0.7% |
| | tg | 7.68 | 7.61 | −0.9% |
| tensor-nomtp-4 | cold pp | 60.7 | 60.7 | −0.1% |
| | warm pp | 47.2 | 47.2 | −0.1% |
| | tg | 11.19 | 11.16 | −0.3% |

**The largest difference is 2.1%.** The likely reason there is no contention despite
a shared host bridge: each card's own x1 link saturates first, so there is no spare
bandwidth to fight over upstream. That is an inference, not a measurement.

Which cells overlapped, and on which GPUs:

| Cells run together | GPUs |
|---|---|
| layer-nomtp-4 ‖ layer-nomtp-2 | 0-3 ‖ 4-5 |
| tensor-nomtp-4 ‖ tensor-nomtp-2 | 0-3 ‖ 4-5 |

| layer-mtp-3 ‖ tensor-mtp-3 | 0-2 ‖ 3-5 |
| tensor-nomtp-3 ‖ (layer-mtp-2 load attempt, failed) | 0-2 ‖ 4-5, first ~5 minutes only |
| layer-nomtp-3, layer-mtp-4 | alone |

### 5-2. `layer-mtp-2` — out of memory on load

```

failed to allocate compute pp buffers
```

| Cause | Verdict |
|---|---|
| Different llama.cpp build | **Ruled out.** Same commit as Gen1 x4, where the cell completed |

## 6. Limits specific to this platform

- **Not a single-variable comparison with Gen1 x4.** The host CPU (EPYC 7232 →
  i7-5820K), RAM (32GB → 16GB), driver and architecture list changed along with the
  link. Prefill and decode are GPU bound and the CPU only tokenizes and samples, so the
  link is taken as the main factor — **but it was not isolated**
- **The single-card baseline is derived**, as at Gen1 x4
- **`layer-mtp-2` is missing** (section 5-2)
- **Nine cells were measured concurrently** (section 5-1)
- **The cards sit on x1 risers**, which also lengthen the electrical path. PCIe error
  counters (AER) were not checked during the run
- Tensor parallelism changes the output as N changes (METHOD 6-2)
