# layer-tensor-parallel-bench

**llama.cpp 레이어 분산 대 텐서 병렬 — GPU 와 인터커넥트를 바꿔가며 실측.**

llama.cpp 의 [멀티 GPU 안내서](https://github.com/ggml-org/llama.cpp/blob/master/docs/multi-gpu.md)는
각 분할 방식이 무엇을 위한 것인지 서술하지만 **실측 수치는 없다.** 이 저장소는
**하나의 동결된 방법론**으로 세 종류의 GPU 를 각각 4장 사용해 실측하였다. 주된 비교 지점은
GPU 종류와 PCIe 대역폭이며, 일부 측정의 경우 NVLink 여부를 포함한다.

측정 대상은 작성자가 실제 운용하는 패턴을 기반으로 했다. 2만 3천 토큰짜리 콜드
프리필 한 번, 그 뒤 프롬프트 캐시가 적중하는 웜 턴 여러 번. **콜드 프리필과 웜
턴에서 분할 방식의 우열이 달라지므로** 양쪽을 다 재야 한다.

**실험 결과 요약**

1. **레이어 분산은 생성 속도를 전혀 사지 못한다.** 사용자 조건에서는 텐서 병렬 2장이
   레이어 분산 4장보다 디코드 속도에서 유리했다. **같은 카드에서는** 링크가 넓을수록
   (Gen1 x1 → x4, PCIe → NVLink) 그 차이가 커진다.
2. **투기적 디코딩(MTP)은 GPU 와 분할 방식에 따라 효용이 뒤집힌다.** 수락률이 거의 같은데도
   P104 에서 16% 손해, V100 에서 3% 이득이다. 같은 카드에서도 레이어를 텐서로 바꾸면 다시
   손해가 된다. 1080 Ti 에서는 전 셀 손해(−7~−17%).
3. **인터커넥트 대역폭과 텐서 병렬 확장.** P104 와 V100 의 확장 효율을 비교하면 V100 쪽이
   대역폭이 16배임에도 확장 효율이 오히려 낮아졌다(4장 57% → 42%). 반면 P104 의 링크를
   x4 에서 x1 으로 줄이자 확장 효율이 나빠졌다. NVLink 는 확장 효율을 개선한다.
4. **분할 방식마다 링크에 대한 반응이 정반대다.** 대역폭을 4분의 1로 줄이면(같은 P104,
   Gen1 x4 → x1) 디코드가 레이어 분산은 4~6%, 텐서 병렬은 24~48% 떨어진다.
5. **카드를 늘리면 텐서 프리필이 느려질 수도, 빨라질 수도 있다.** 2장 → 4장에서 텐서 콜드
   프리필이 PCIe V100 은 떨어지고(1,141 → 887 t/s) 1080 Ti(337 → 461)와 NVLink 는 오른다.
